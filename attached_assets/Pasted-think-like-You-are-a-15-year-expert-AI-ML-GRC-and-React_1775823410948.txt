Core Engineering Principle
Every module in Sentinel should either create, enrich, evaluate, approve, or consume one of a small set of canonical governed entities. If a module has its own disconnected records, its own status semantics, and its own attachment model, the platform will fragment operationally even if the UI appears complete.

The engineering goal should be a shared domain model with many projections, not many duplicate mini-systems. In practice, this means Model Inventory, Agent Discovery, Use Cases, Risks, Controls, Evidence, Audits, Vendors, Incidents, Assessments, Policies, and Trust Scores should all resolve to linked records in a common platform graph.
